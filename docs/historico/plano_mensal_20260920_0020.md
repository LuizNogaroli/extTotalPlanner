# Plano Mensal (mesmo esquema do Plano Anual) + Refatoração Compartilhada
**Data:** 20 de Setembro de 2026

## O que foi feito
O usuário pediu que o Plano Mensal adotasse "o mesmo esquema" do Plano Anual — texto único versionado, com card "atual" + histórico de versões. Como os dois passariam a compartilhar exatamente a mesma lógica de renderização e de salvamento (mudando só o `type` armazenado, o rótulo e o ícone), aproveitei para extrair essa lógica repetida em funções auxiliares reutilizáveis, evitando triplicar o código quando o Plano Semanal for implementado com o mesmo padrão mais adiante.

## 1. Estado Anterior (Antes)
- `switchToPlanosView()` tinha toda a lógica de renderização do Plano Anual (card atual + histórico) escrita diretamente dentro da função, específica para `type === 'plano_anual'`.
- O Plano Mensal só mostrava o placeholder "🚧 em construção" (não tinha `form-plano_mensal`, nem registro em `FORM_REGISTRY`, nem lógica de salvamento).
- O listener de `crudSave` tinha um bloco `else if (type === 'plano_anual')` isolado, sem generalização.

## 2. Estado Novo (Depois)
1. **`index.html`**: novo `<form id="form-plano_mensal">` no modal CRUD (após `form-plano_anual`), com `<textarea id="plano_mensal-content">` — mesmo padrão de `form-plano_anual`.
2. **`js/modules/formMappers.js`**: novo registro `'plano_mensal'` em `FORM_REGISTRY`, espelhando `'plano_anual'`.
3. **`js/modules/formLoaders.js`**: adicionado `'plano_mensal': this.loadBasicForm.bind(this)`.
4. **`js/modules/crudModal.js`**: `'plano_mensal'` adicionado a `SELF_MANAGED_TYPES`.
5. **`js/app.js`** (refatoração):
   - Nova função `async function renderPlanoVersionado(contentArea, tipo, label, icone)`, extraída do bloco que antes só existia para `plano_anual` dentro de `switchToPlanosView()`. Renderiza o botão "✏️ Atualizar {label}", o card "{label} Atual" (com ícone e cor dinâmicos) e, se houver, a seção "{label} (versões anteriores)".
   - `switchToPlanosView()` simplificada: para `prazo === 'anual'` chama `renderPlanoVersionado(contentArea, 'plano_anual', 'Plano Anual', '📅')`; para `prazo === 'mensal'` chama `renderPlanoVersionado(contentArea, 'plano_mensal', 'Plano Mensal', '🗓️')`; `'semanal'` continua com o placeholder "em construção".
   - O bloco `else if (type === 'plano_anual')` do listener `crudSave` foi generalizado para `else if (type === 'plano_anual' || type === 'plano_mensal')`, com a lógica de versionamento (mover atual para histórico, criar novo registro) parametrizada por `type` em vez de hardcoded para `'plano_anual'`. O prazo a re-renderizar (`'anual'` ou `'mensal'`) é derivado do `type` recebido.
6. Testado: cadastro de um Plano Mensal confirmando (a) card "🗓️ Plano Mensal Atual" com data válida, (b) zero registros "fantasma" no storage, e (c) que o Plano Anual continuou funcionando normalmente após a refatoração (navegado e conferido isoladamente). Dados de teste removidos ao final.

## 3. Plano de Rollback / Desfazer
1. Em `index.html`: remover o bloco `<form id="form-plano_mensal">...</form>`.
2. Em `js/modules/formMappers.js`: remover a entrada `'plano_mensal'` de `FORM_REGISTRY`.
3. Em `js/modules/formLoaders.js`: remover a linha `'plano_mensal': this.loadBasicForm.bind(this)`.
4. Em `js/modules/crudModal.js`: remover `'plano_mensal'` do array `SELF_MANAGED_TYPES`.
5. Em `js/app.js`: reverter `switchToPlanosView()` para tratar apenas `prazo === 'anual'` com o bloco de renderização inline (ver `docs/historico/plano_anual_20260919_2350.md` para o código original antes da extração do helper), e reverter o bloco `crudSave` para `else if (type === 'plano_anual')` isolado. A função `renderPlanoVersionado()` pode ser removida se nenhum outro plano (ex.: Semanal) ainda a estiver usando.
