# Nível Tático: Página de Planos + Plano Anual
**Data:** 19 de Setembro de 2026

## O que foi feito
Foi iniciado o Nível 3 (Tático) da pirâmide de planejamento do extPlanner (Estratégico → Horizontes → **Tático** → Operacional): a página "Planos", acessada pelo menu lateral `Tático → Planos` (que até então existia no HTML mas não tinha nenhuma ação associada ao clique). A página tem três sub-abas — **Anual**, **Mensal** e **Semanal** — e, como combinado com o usuário, começamos implementando o Plano Anual, seguindo exatamente o mesmo padrão texto-único-versionado já usado em Missão/Visão/Objetivos (não uma lista de marcos com data, que era a alternativa cogitada — o usuário optou pela consistência com o padrão existente). Também ficou definido que os marcos do Plano Anual não precisam, por ora, se vincular formalmente a um Objetivo de Curto Prazo específico.

Mensal e Semanal ainda não têm implementação — a aba existe e é navegável, mas mostra um aviso "🚧 em construção", preparando o terreno para as próximas rodadas sem quebrar a navegação.

## 1. Estado Anterior (Antes)
- O link "Planos" no menu lateral (`Tático`) existia no HTML sem `id` e sem nenhum listener — clicar nele não fazia nada.
- Os botões do cabeçalho `btn-nav-anual`/`btn-nav-mensal`/`btn-nav-semanal` (parte da barra de navegação estática do topo) também não tinham listener — são um elemento visual separado, não conectado a esta nova página.
- Não havia registro `plano_anual` em `FORM_REGISTRY`, nem view, nem formulário para isso.

## 2. Estado Novo (Depois)
1. **`index.html`**:
   - Adicionado `id="menu-planos"` ao link "Planos" do menu lateral Tático.
   - Nova `<div id="view-planos">` dentro de `<main>`, como irmã de `view-strategic`/`view-objetivos-educacional`/`view-export`. Contém uma barra de sub-abas (`.planos-tab-btn`, com `data-prazo="anual"|"mensal"|"semanal"`) e um container `#planos-content-cards` onde o conteúdo de cada aba é renderizado dinamicamente.
   - Novo `<form id="form-plano_anual">` no modal CRUD (após `form-objetivos`), com um único campo `<textarea id="plano_anual-content">` — igual ao padrão de `form-missao`/`form-visao`.
2. **`js/modules/formMappers.js`**: novo registro `'plano_anual'` em `FORM_REGISTRY`, espelhando `'missao'`/`'visao'` (`fields: ['id','type','content','timestamp']`, `defaults: {type:'plano_anual'}`, `required: ['content']`).
3. **`js/modules/formLoaders.js`**: adicionado `'plano_anual': this.loadBasicForm.bind(this)`.
4. **`js/modules/crudModal.js`**: `'plano_anual'` adicionado a `SELF_MANAGED_TYPES` desde o início (evitando de partida o bug de duplicação/"Invalid Date" já documentado nas seções 3.10 e histórico anterior).
5. **`js/app.js`**:
   - `document.getElementById('menu-planos').addEventListener('click', () => switchToPlanosView('anual'))`.
   - Nova função `async function switchToPlanosView(prazo = 'anual')`: mostra `view-planos`, atualiza o estilo visual de qual aba está ativa (`.planos-tab-btn`), registra os listeners de clique das abas uma única vez (flag `btnPlanosTabsListenersAttached`, igual ao padrão dos botões "Voltar"), e renderiza o conteúdo de `#planos-content-cards` conforme o `prazo`:
     - `'anual'`: mesmo layout "atual + histórico" de Missão/Visão/Objetivos, com botão "✏️ Atualizar Plano Anual" (`crudModal.open('plano_anual')`).
     - `'mensal'` / `'semanal'`: placeholder "🚧 ainda está em construção".
   - Nova variável de estado `let currentPlanosTab = 'anual';`, usada para saber (após um save) se deve re-renderizar a página de Planos.
   - Novo bloco `else if (type === 'plano_anual')` no listener de `crudSave`, com a mesma lógica de versionamento (move o atual para o histórico, cria um novo com `id`/`timestamp` frescos) — mas checando a visibilidade de `view-planos` (não `viewStrategic`, já que Planos é uma view própria) e `currentPlanosTab === 'anual'` antes de re-renderizar.
   - `hideAllViews()` passou a incluir `'view-planos'`.
6. Testado: cadastro de um Plano Anual e depois uma segunda versão, confirmando (a) card "atual" exibindo a versão mais recente com data válida, (b) a versão anterior migrando corretamente para "Plano Anual (versões anteriores)", e (c) zero registros "fantasma" no storage bruto. Dados de teste removidos ao final.
